# 0006. SPA を普段の入口にし、MPA と HTML の形と CSS を共通にする

## ステータス

承認（2026-11-19）

## コンテキスト

ユーザー登録を、Django のフォームの画面（MPA）と React の画面（SPA）の両方で提供する。同じ機能を 2 通りの画面で作るので、それぞれの役割と、見た目をどうそろえるかを決める必要がある。

入口の役割として、次の 2 つを比べた。

- MPA を普段の入口にし、SPA を別に用意する: JavaScript がなくても使える画面が表に出る。ただし、入力しながらの検証という SPA の良さが、普段の入口で生きない。
- SPA を普段の入口にし、MPA は JavaScript が使えない人の入口にする: 普段は入力しながら検証でき、JavaScript が使えない人も MPA で登録できる。

見た目のそろえ方として、次の 2 つを比べた。

- 画面ごとに作る: それぞれの技術に合った書き方ができる。ただし、同じフォームの見た目と読み上げの扱いを 2 回作り、ずれやすい。
- HTML の形と CSS を共通にする: 1 つの欄のマークアップ（クラス名、`aria-invalid`、`aria-describedby`）を両方で同じにし、同じ CSS を読む。MPA は JavaScript なしで表現できる範囲に収める必要がある。

## 決定

SPA を普段の入口にし、MPA は JavaScript が使えない人の入口にする。2 つの画面は、1 つの欄の HTML の形と CSS を共通にする。見た目は MPA で JavaScript なしで表現できる範囲で決め、SPA は同じ形を React で組む。検証のルールは 2 つの画面とサーバーでそろえ、入力しながらの検証は SPA だけが行う。

## 結果

- サイトの入口は SPA に移り、JavaScript が使えない人には MPA へ案内する。
- 見た目と読み上げの扱いが、2 つの画面で同じになる。CSS は 1 つで済む。
- 見た目を変えるときは、MPA のテンプレートと SPA の部品の両方の HTML の形を、同じに保つ必要がある。
- 検証のルールは、サーバーと SPA の 2 か所に書くことになる。メッセージの文は、画面に合わせて変えてよい。
