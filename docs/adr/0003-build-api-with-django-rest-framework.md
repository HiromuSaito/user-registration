# 0003. API は Django REST Framework で作る

## ステータス

承認（2026-11-14）

## コンテキスト

ユーザー登録の API を作るにあたり、Django REST Framework（DRF）と Graphene-Django（GraphQL）を比べた。

API で必要な操作は、都道府県の一覧を取ることと、ユーザーを登録することの 2 つだけである。登録では、登録画面のフォームと同じ検証のルールを使い、フロントは検証のエラーを項目ごとに受け取って表示する。

検討した案は次のとおり。

- Graphene-Django: 取る側が欲しいデータの形を決められるのが強みだが、操作が 2 つだけなので生きない。検証のエラーはレスポンスの中で返すのが一般的で、項目ごとの返し方は自分で決めることになる。
- DRF: 検証のルールをシリアライザのフィールドに、フォームとほぼ同じ書き方で付けられる。検証のエラーは 400 のレスポンスで項目ごとに返る。

## 決定

API は DRF で作る。

## 結果

- フォームと同じ検証のルールを、API でもそのまま使える。
- フロントは、API が返すエラーをそのまま項目ごとに表示できる。
- 取る側がデータの形を決めることはできない。
- GraphQL に変える場合は、フロントの API の呼び方も作り直すことになる。
