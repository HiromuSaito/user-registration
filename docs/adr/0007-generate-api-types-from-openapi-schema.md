# 0007. API の型は OpenAPI のスキーマから生成し、スキーマと型をコミットする

## ステータス

承認（2026-11-19）

## コンテキスト

SPA は、都道府県の一覧の取得と、ユーザーの登録の 2 つの API を呼ぶ。Django 側の項目を変えたときに、SPA が送る値や受け取る値とずれないようにしたい。API の仕様は drf-spectacular で OpenAPI のスキーマとして出している。

API の呼び方として、次の 3 つを比べた。

- 型を手で書く: 依存は増えないが、Django 側を変えても型が追いつかず、ずれに気づけない。
- スキーマから型だけを生成し、呼び出しは自分で書く: Django 側の変更が型に表れ、ずれを型チェックで見つけられる。実行時に使う依存は増えない。
- スキーマから API のクライアントまで生成する: 書くコードは減り、URL まで型で守られる。ただし、呼ぶ API が 2 つだけでは生成物の量に見合わず、生成されたコードを読んで説明する負担が増える。

生成したものの扱いとして、次の 2 つを比べた。

- コミットせず、型チェックやビルドの前に毎回生成する: 生成物はリポジトリに入らないが、フロントの型チェックだけでも Python と Django の環境が要り、API の変更が差分に出ない。
- スキーマと型をコミットし、CI で最新か確かめる: API の変更がスキーマの差分としてレビューに出る。フロントの型チェックやビルドに Python が要らない。

## 決定

API の型は、OpenAPI のスキーマから openapi-typescript で生成し、呼び出しは `fetch` で自分で書く。スキーマと型はコミットし、CI で、スキーマが Django のコードと、型がスキーマと一致しているかを確かめる。

## 結果

- Django 側で API に送る項目が増えると、SPA の型チェックで気づける。項目が消えたずれは、型では見つけられない。
- API を変えたときは、スキーマと型を作り直してコミットする必要がある。作り直し忘れは CI で止まる。
- 検証のルール（文字数や使える文字など）はスキーマにほとんど載らないため、型の生成とは別に、SPA の側で書く。
- openapi-typescript は TypeScript のコンパイラーの API を使うため、それを持たない TypeScript 7 には上げられない。
